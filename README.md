# Chirpy

Chirpy is an HTTP backend in Go for a small social network. The project allows users to register, authenticate with JWT, create and query chirps, renew and revoke refresh tokens, and handle a user upgrade webhook.

## Technologies used

- Go
- PostgreSQL
- net/http
- sqlc
- JWT
- Argon2id
- godotenv
- UUID

## Folder descriptions

- `main.go`: application entry point.
- `internal/server`: contains the HTTP router, handlers, middleware, and server configuration.
- `internal/auth`: logic related to JWT, bearer tokens, refresh tokens, password hashing, and validation.
- `internal/database`: code generated by sqlc to interact with PostgreSQL.
- `sql/schema`: SQL migrations to create and modify tables.
- `sql/queries`: SQL queries used by sqlc.
- `requests.http`: example HTTP requests to test the API.

## Environment variables

The application expects these variables:

```env
DB_URL=postgres://user:password@localhost:5432/chirpy?sslmode=disable
PLATFORM=dev
JWT_SECRET=your_secret
POLKA_KEY=your_polka_key
```

## Data model

### Users

- `id`: UUID
- `created_at`: timestamp
- `updated_at`: timestamp
- `email`: unique text
- `hashed_password`: hashed password
- `is_chirpy_red`: boolean

### Chirps

- `id`: UUID
- `created_at`: timestamp
- `updated_at`: timestamp
- `body`: text
- `user_id`: UUID of the author

### Refresh tokens

- `token`: text
- `created_at`: timestamp
- `updated_at`: timestamp
- `user_id`: UUID
- `expires_at`: timestamp
- `revoked_at`: nullable timestamp

## Main endpoints

### Health and administration

- `GET /api/healthz`
- `GET /admin/metrics`
- `POST /admin/reset`

### Users

- `POST /api/users`
- `POST /api/login`
- `PUT /api/users`

### Chirps

- `GET /api/chirps`
- `GET /api/chirps/{chirpID}`
- `POST /api/chirps`
- `DELETE /api/chirps/{chirpID}`

### Tokens

- `POST /api/refresh`
- `POST /api/revoke`

### Webhook

- `POST /api/polka/webhooks`

## Authentication flow

1. The user creates an account with `POST /api/users`.
2. Then they sign in with `POST /api/login`.
3. The server returns an access JWT and a refresh token.
4. Protected endpoints use the following header:

   ```http
   Authorization: Bearer <token>
   ```

5. The refresh token can be used in `POST /api/refresh` to obtain a new access token.
6. `POST /api/revoke` revokes the refresh token.

## How to run the project

1. Have PostgreSQL running.
2. Create the database.
3. Configure the environment variables.
4. Run the SQL migrations located in `sql/schema`.
5. Run the project:

```bash
go run .
```

## Additional notes

- The `POST /admin/reset` endpoint only works when `PLATFORM=dev`.
- Chirps go through a word-censorship function when returned.
- The metrics middleware counts how many times static content from `/app/` has been served.
